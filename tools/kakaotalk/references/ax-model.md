## 왜 접근성 API인가

| 경로 | 결과 |
|---|---|
| 로컬 DB(`~/Library/Containers/com.kakao.KakaoTalkMac/.../<hash>`) | SQLCipher 계열 암호화 — 헤더가 `SQLite format 3`이 아님 |
| 디버거 부착(LLDB 등) | hardened runtime + `get-task-allow` 없음 + SIP → 거부 |
| 접근성 API | 화면에 그려진 UI 텍스트를 구조적으로 읽음 — 이 스킬의 방식 |

## 창 구조

- 메인 창 제목 `카카오톡`. 채팅 목록 `AXTable`의 각 행 셀에 `AXIdentifier`로 구분된 요소가 있다:
  `_NS:40` 방 이름, `Count Label` 안 읽은 수, `_NS:69` 마지막 시간, `AXScrollArea > AXTextArea` 미리보기,
  `AXImage desc="badge me"` 나와의 채팅.
- 대화방 창 제목 = 방 이름. 첫 `AXScrollArea > AXTable`이 메시지 목록, `AXTextArea desc="메시지 입력"`이 입력칸,
  아래쪽에서 가장 넓은 이름 없는 버튼이 전송 버튼(누르지 않는다 — 거짓 성공).
- 메시지 테이블은 화면에 보이는 행만이 아니라 **불러온 행 전체**를 노출한다(보이는 4행 / 노출 75행 실측).
  스크롤바 `AXValue = 0`이면 약 50행씩 더 불러온다.
- 빈 제목의 대화방 창(오픈채팅 빈 방 등)이 있을 수 있다 — 방 식별은 제목 일치 + 입력칸 존재로만 한다.

## 행 분류 규칙

`kakaotalk-ax rows`는 행마다 요소 목록(`role`, `value`, `desc`, 창 기준 `x`, `w`, `h`)을 낸다. `normalize`가 분류한다.

| 종류 | 판정 |
|---|---|
| `spacer` | 요소 없음 |
| `date` | 설명 없는 `AXButton` 하나뿐 — 날짜 글자는 그림이라 AX로 안 읽힘(OCR 필요) |
| `system` | 텍스트 요소 하나뿐(예: "메시지가 삭제되었습니다.") |
| `text` | `AXTextArea` 있음. 링크 미리보기는 여러 개 → `parts` |
| `media` | 텍스트 없이 큰 `AXImage`(폭 40 초과) — 사진·이모티콘 |

- `mine`: 프로필 버튼이 없고 본문 요소의 오른쪽 끝이 창 폭−30 이상. 상대 말풍선은 x≈60에서 시작한다.
- `sender`: 프로필 버튼이 있는 행의 시간 아닌 `AXStaticText`. 같은 사람의 연속 메시지는 화면처럼 이름이 빠지므로
  직전 상대 메시지의 이름을 이어받고 `sender_inferred: true`. 날짜·시스템 행이나 내 메시지에서 끊긴다.
- `time`: `오전/오후 H:MM` → 24시간 `HH:MM`. 같은 분·같은 사람의 묶음은 마지막 말풍선에만 시간이 있어서,
  뒤 메시지의 시간을 앞으로 채우고 `time_inferred: true`.

## 메시지 출력 필드

`i`(행 번호), `kind`, `mine`, `sender`, `time`, `date`(`--dates` 시), `text`, `parts`, `media`(`--media` 시 `ocr`,
`partial`, `image`), `sender_inferred`, `time_inferred`, `send_failed`(내 메시지에 재전송·삭제 버튼).
새로 연 창은 행 개수만 먼저 잡히고 내용이 약 1초 뒤 채워진다 — `read`는 보이는 행이 채워질 때까지 기다린다. 읽은 결과의 `warnings`에 OCR 실패를 담는다.

## 백그라운드 동작 실측

| 상태 | 읽기 | 방 열기 | 전송 | 캡처·OCR |
|---|---|---|---|---|
| 카카오톡이 뒤에 있음(가려짐) | ✅ | ✅ (다른 대화창이 key일 땐 실패 가능 → `--activate`) | ✅ | ✅ |
| 앱 숨김(⌘H) | ✅ | 미확인 | ✅ | ❌ |
| 대화창 최소화 | ✅ | — | ❌ (`--unminimize` 필요) | ❌ |
| 화면 잠금 | 미확인 | 미확인 | 미확인 | ❌ |

- 전송 판정: 보내기 전후로 "같은 문구 + 오른쪽 정렬" 행을 센다. 시간 표시가 붙은 행이 늘면 `sent`, 시간 없이 이름 없는
  버튼 2개(재전송·삭제)가 붙은 행이 늘면 `failed-in-app`. 실패한 메시지는 대화 맨 아래에 계속 고정되므로 새 메시지가
  마지막 행이라고 가정하지 않는다. 같은 문구를 같은 분에 연달아 보내면 앞 행의 시간이 사라져 `unverified`가 날 수 있다.
- 전송은 입력칸 `AXFocused` → `AXValue` 설정 → 값 재확인 → Return 키 이벤트를 카카오톡 PID로 직접 보낸다.
  `AXPress`(전송 버튼)·`AXConfirm`·`AXUIElementPostKeyboardEvent`는 전송되지 않았다.
- 방 열기는 메인 창 목록 행 선택 + Return. Return은 앱의 key 창으로 가므로, 다른 대화창 입력칸에 글이 있으면
  그 글이 엉뚱한 방으로 전송될 수 있다 → `other-window-has-draft`로 거부한다.
- 활성화 후 포커스를 옮기면 입력칸 값이 잘린 사례가 있었다(한글 IME 추정) → 값 재확인 불일치면 비우고 실패.

## OCR 보완

- macOS Vision(`ko-KR`, `en-US`, accurate)으로 로컬에서만 처리한다. 화면 기록 권한이 필요하다.
- 창 번호로 그 창만 캡처하므로 다른 창에 가려져 있어도 된다. 최소화·숨김 상태는 불가.
- 캡처 전 해당 행을 화면 중앙으로 스크롤하고, 메시지 영역과 겹치는 부분만 잘라 입력칸이 섞이지 않게 한다.
- 1배율 화면에서는 작은 한글을 잘못 읽어 3배 확대 후 OCR한다(날짜 31개 중 29 → 30개 인식 실측).
- 날짜는 `YYYY년 M월 D일` 패턴만 채택하고, 앞 날짜보다 이르면 `non-monotonic`으로 버린다.
