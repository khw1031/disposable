## Result

입력: 요구사항 여섯 가지(다시 만들기 0). 예시는 세계관 「우주 한가운데 떠 있는 밤의 미술관」, 실제 장소 레퍼런스 「렌초 피아노의 메닐 컬렉션·바이엘러 재단」, 놓을 콘텐츠 「방문자의 사진 한 장」이다.
출력: 브라우저 주소 하나로 열리는 3D 세계. 예시인 호호 미술관에서는 이렇게 됐다.
- 입구: 로딩 화면에서 아치형 「빛의 문」이 열리고, 빛 속으로 들어가면 로비가 나온다
- 공간: 흰 회벽·오크 바닥의 사실적인 건물이 밤으로 바뀐다. 천장에 오로라가 숨 쉬듯 흐르고, 창밖으로 우주가 보인다
- 걷기: 내 캐릭터를 뒤에서 따라가는 3인칭 시점으로 걷는다. 작품을 누르면 캐릭터가 작품 앞에 서고, 카메라가 뒤에서 캐릭터와 작품을 함께 잡는다
- 함께: 같은 때 들어온 방문자가 자동 이름과 옷 색으로 보이고, 인사를 주고받는다
- 소리: 배경 음악과 걸음·누르기 효과음이 나고, 끌 수 있다

## Before you start

- Blender(Cycles 굽기와 백그라운드 Python 실행)
- Node.js, three.js 0.187, vgpu 0.6(WGSL 함수를 three 재질에 잇는 데만 쓴다), ffmpeg
- 공개할 곳: 정적 파일 호스팅과 WebSocket 방 하나. 여기서는 Cloudflare Workers와 Durable Objects를 썼다
- 재질 사진(벽·바닥·돌·창밖 풍경 등)을 만들 이미지 생성 도구. 창 밖 영상과 배경 음악용 생성 도구는 선택이다

## Quick start

## Rebuild

원칙: 공간은 실제 장소처럼 사실적으로 짓고, 분위기는 빛으로 더한다. 세계에 놓이는 콘텐츠(사진·영상)는 효과와 색 보정에서 빼고 원래 색 그대로 둔다. 아래 수치는 예시인 호호 미술관에서 쓴 값이고, 「다른 세계면」은 미술관에서 해 보지 않은 일이다.

0. 요구사항과 바꿀 자리
- 요구사항 여섯 가지: (1) 세계관 한 줄 (2) 실제 장소 레퍼런스 하나(건물이든 야외든) (3) 걷기 말고 사람들이 거기서 하는 일(보기·앉기·모이기 등) (4) 놓을 콘텐츠: 무엇(이미지·영상·없음)을 몇 개, 어떻게 넣나(운영자가 목록 파일로 넣기 또는 방문자가 올리기. 올리기는 이 레시피에 없다) (5) 규모: 콘텐츠 자리 수와 늘어나는 단위 (6) 분위기(밤·네온 등)가 WebGL2 브라우저에서도 보여야 하나. (6)이 빛을 굽는 방식을 정한다(5 참고).
- 바꿀 자리: Lobby·Hall 모듈 → 입구 모듈과 반복 구역(야외면 땅 한 판) / slot 벽 평면 1.6×1.2m·관당 8개 → 콘텐츠 자리의 모양과 개수(벽 평면·화면·의자 등) / 캔버스와 감상 구도 수치 → 콘텐츠 크기에 맞춰 다시 / 굽는 광원 → 세계의 광원 / 오로라·별가루·물빛·안개 → 세계의 분위기 효과(배율 방식만 옮김) / 자동 이름 낱말·효과음 이름 → 세계의 낱말.
- 그대로 쓰는 것: 캐릭터·3인칭·이동·카메라(7), 실시간 접속의 방 구조와 요청 아끼기(8), 소리 처리(9), 로딩·UI·공개(10), 라이트맵 인코딩 수치(3). 실시간 접속의 메시지는 (3)의 행동에 맞춰 늘린다(8 참고).

1. 세계관 정하기
- 한 줄 세계관과 실제 장소 레퍼런스를 함께 정한다. 미술관에서는 처음에 상상으로 만든 「신비로운 공간」 시안 4종(명상실·하늘 구멍·빛의 십자가·무한 거울방)을 "실제 공간 같지 않다"는 이유로 모두 버렸다. 실제 미술관(루버 천장의 자연광, 흰 회벽, 오크 바닥)을 사실적으로 지은 뒤 "같은 건물의 밤"으로 바꾼 쪽이 통했다. 밤의 레퍼런스는 어둡고 천창 빛이 변하는 명상 공간, 색 안개, 어두운 홀의 인공 태양 같은 설치 작품이었다.
- 결정은 나란히 비교해서 한다. 주소 쿼리(?theme=, ?fx=)로 시안과 효과를 켜고 끄며, 비교 페이지 하나에 같은 자리·같은 시각의 화면을 모은다. 개발 중에는 카메라 자리와 효과 시계를 고정하는 함수를 열어 둔다.

2. 공간 모듈(Blender, 스크립트로만)
- .blend를 손으로 고치지 않고 Python 스크립트로 짓는다: blender -b --factory-startup -P build.py -- --stages uv,bake,export. 벤치·조명 같은 소품도 같은 스크립트로 만든다.
- 미술관 GLB 최상위는 Lobby와 Hall 두 모듈이다. Hall에는 커스텀 속성 hall_length(기본 24m)를 두고, 앱이 이 모듈을 복제해 전시관을 늘린다.
- 이름 규칙: slot_01~slot_08 콘텐츠 자리 평면(미술관은 1.6×1.2m, 벽 안쪽을 향함), wall_*·col_* 충돌 상자, floor_* 바닥(누르면 그 자리로 걸어감), spawn 시작점, hall_anchor 북쪽 문·hall_anchor_s 남쪽 문(관을 붙이는 기준점), hall_end_cap 막힌 끝. 문은 3m×3.2m다.
- 장면 스크립트는 「이 점이 실내 공기인가」를 판정하는 함수(is_air)도 함께 넘긴다. 3의 보이는 면 분류가 쓴다.
- 재질은 이미지 생성 도구로 만든 회벽·오크·블루스톤·콘크리트·트래버틴과 창밖 풍경을 썼다. UV0은 미터 단위로 펴고 재질마다 타일 크기로 나눈다.
- 다른 세계면: 충돌은 상자만 써 봤다. 나무 기둥처럼 둥근 것은 상자로 근사하거나 새로 정하고, 높낮이 있는 땅·바깥 경계도 새로 정한다.
- 확인: 앱이 필수 이름(미술관은 Lobby·Hall·slot_01~08)을 찾지 못하면 오류를 내게 해서 이름이 틀린 GLB를 바로 잡는다.

3. 빛 굽기(라이트맵)
- 굽는 광원은 모두 발광 면이다. 미술관은 천창 위 하늘빛 판(#E9F0F7, 세기 1.6), 창 풍경 그림 판(세기 1.15), 3800K 조명 렌즈(세기 30)로 구웠다. 다른 세계면 네온관·모닥불·가로등도 발광 재질로 함께 굽는다.
- 단계: UV0 정리 → 보이는 면 분류(면 바로 앞의 표본점이 is_air 안, 벽 상자 밖에 있어야 보임. 안 보이는 면은 아틀라스 면적 0) → UV1 "lightmap"(smart project 66°, 모듈마다 2048 아틀라스 하나, 여백 0.0045) → Cycles DIFFUSE 굽기(Direct+Indirect, Color 끔, float, 256샘플) → OIDN 노이즈 제거 → 인코딩(선형값을 S로 나눠 sRGB 8비트로. 상위 99.5% 값이 0.9에 오게 S를 정하고, S는 JSON 목록에 적는다) → GLB 내보내기(UV0 타일, UV1 라이트맵, JPEG 재질).
- 굽는 시간은 작업한 맥에서 로비 65초, 전시관 46초였다. 문을 새로 내면 다시 굽는다. 굽기 때만 180° 돌린 전시관을 남쪽 문 뒤에 둔다.
- 라이트맵은 WebP near-lossless(quality 60)로 저장한다. 일반 손실 WebP(q92)는 블록 오차(최대 36/255)가 라이트맵 배율로 커져서 작품 앞 벽에 얼룩 블록이 보였다. near-lossless는 최대 오차 2/255이고, 장당 약 1.7MB다.
- 다른 세계면: 보이는 면 분류와 is_air는 실내용이라 야외는 이 분류 없이 굽는다. 넓은 땅은 2048 하나로 해상도가 모자랄 수 있어 여러 조각(모듈)으로 나눠 굽는다. 잎처럼 투명한 면, 어두운 장면에 밝은 광원 하나(모닥불)일 때 인코딩 수치가 버티는지는 해 보지 않았다.
- 확인: 손실 압축본과 PNG를 같은 자리에서 찍어 표면의 블록 얼룩을 비교한다.

4. 웹 렌더(three.js)
- new WebGPURenderer({ antialias: true }) 후 await renderer.init(). WebGPU가 없으면 three가 WebGL2로 바꾼다. 픽셀 비율은 휴대폰 1.5, 그 밖 2를 넘기지 않는다. 카메라는 시야각 56°, near 0.05, far 220이다(실내 기준. 트인 야외는 far와 안개를 다시 정한다).
- 렌더러 톤매핑은 끈다. Cycles와 같은 AgX를 공간 재질의 outputNode에만 걸어서 콘텐츠(사진·영상)는 원래 색으로 보이게 한다. 공간 재질은 lightMap(UV1)과 lightMapIntensity = S × 세기(JSON 목록의 intensity, 없으면 π)를 쓴다.
- 미술관은 Hall 모듈을 복제해 짓는다. 관 번호 0, 2, 4…는 로비 북쪽 문, 1, 3, 5…는 남쪽 문(180° 회전)에 번갈아 붙여 걷는 거리를 줄인다. 관은 방문자가 가까이 가거나 바로가기(메뉴에서 그 관으로 순간 이동)로 갈 때 처음 짓고, 콘텐츠 자리 좌표는 템플릿에서 계산해 짓기 전에도 안다. 최소 2관이다.
- 로딩 진행 비율: 렌더러 0.1, 라이트맵 0.18, GLB 0.24~0.92(받은 바이트 비율), 첫 프레임을 그리면 준비 끝.

5. 분위기 효과(WGSL)
- 구조: 미술관은 낮의 빛으로 굽고, 밤은 그 위에 WebGPU에서만 곱하는 효과로 만들었다. 그래서 WebGL2 브라우저에서는 낮으로 보인다. 요구사항 (6)이 「예」면 그 분위기(밤·네온) 자체로 굽고, 효과는 그 위의 덤으로 둔다(다른 세계면).
- 연결: .wgsl 파일을 vgpu의 번들러 규칙(@vgpu/wgsl의 wgslTurbopackRule)으로 모듈처럼 import하고, vgpu/three의 tslExports(그 모듈)("함수이름")으로 바인딩 없는 순수 WGSL 함수(export fn)만 TSL 노드로 바꿔 재질에 잇는다. three가 GPU 장치를 가지므로 vgpu의 전체 화면 패스는 쓰지 않는다(번짐 같은 three 자체 후처리는 시험하지 않았다). 효과는 AgX 직전의 구운 빛에 곱하는 배율이고, 끈 효과는 노드를 만들지 않는다.
- 오로라: 실내 구운 빛 0.07배. 천장과 벽 위쪽에 약 6m 간격의 오로라 띠(청록·초록·보라·장밋빛, 바닥으로 갈수록 옅음)가 20여 초 주기로 숨 쉬듯 밝아진다. 천창 유리는 별이 반짝이는 밤하늘(유리 재질에 WGSL 하늘 함수를 잇는다), 캔버스 옆면·캡션은 0.8배, 광고 화면은 0.6배. 다른 세계면 야외 하늘 전체는 큰 하늘 돔 재질에 같은 방식으로 잇는다.
- 별가루: instanced Sprite 360개가 보는 사람 둘레 14m 상자 안을 감싸 돈다. 위치·반짝임·색은 WGSL에서 계산한다(다른 세계면 반딧불·불티로 바꿔 쓸 수 있다).
- 함께 켜는 효과: 하늘의 시간(천창 구름 그림자 ±4%, 방문자 시각의 빛 색), 물빛(창 가까운 천장에 연못 반사 일렁임), 정원 안개. 일렁이는 불빛처럼 움직이는 빛도 같은 배율 방식으로 만든다(다른 세계면).
- 뺀 효과: 햇살 속 먼지 기둥(구운 공간에 그림자 없는 직사광을 얹으면 붙인 티가 남), 작품 앞 공기 흔들림(사진을 일그러뜨림).
- 창 밖 우주: 생성한 16:9 8초 영상에서 가로 띠를 잘라 앞뒤로 이어 끊김 없는 16초 반복을 만든다(2.5MB). 영상 판을 창보다 1.7m 뒤에 판 폭 전체로 펴고, 범위 밖은 거울 반복으로 처리해 가장자리가 늘어지지 않게 한다.
    ffmpeg -i space.mp4 -filter_complex "[0:v]crop=1280:356:0:52,split[a][b];[b]reverse[r];[a][r]concat=n=2:v=1:a=0,format=yuv420p[v]" -map "[v]" -an -c:v libx264 -preset slow -crf 24 -movflags +faststart -r 24 space-window.mp4
- 확인: 효과를 모두 끈 화면이 효과 도입 전과 픽셀 차이 0이고, 효과를 켜도 콘텐츠 픽셀은 바뀌지 않는다.

6. 콘텐츠 자리(미술관: 작품)
- 자리마다 받는 데이터: 자리 번호, 이미지 주소·썸네일 주소, 가로세로 크기, 제목, 만든 이(미술관은 설명·대표색도). 미술관은 서비스 DB가 주지만, 올리기 없이 시작하면 같은 모양의 목록 파일로 넣으면 된다.
- 미술관은 액자 없이 갤러리 랩 캔버스로 건다: 두께 3.8cm, 벽에서 1.2cm, 옆면에는 이미지 가장자리(이미지 폭의 1.8%)가 감겨 들어가고 벽에 부드러운 접촉 그림자가 진다.
- 누르면 감상 자리로 옮긴다. 먼저 1인칭 기준 거리를 구한다: 콘텐츠 가운데를 마주 보고, 콘텐츠가 화면 세로 58%·가로 62% 안에 드는 거리(1.4~3.6m). 그 자리가 충돌 상자 안이면 콘텐츠 쪽으로 0.15m씩 다가선다(세로 휴대폰에서 벤치 위에 서던 문제).
- 3인칭에서는 캐릭터가 그 거리의 0.6배(1.3~2.2m, 막히면 0.4m씩 물러남) 앞에 서서 콘텐츠를 보고, 카메라는 3.3m 뒤에서 콘텐츠 높이에 맞춰 최대 0.6m 올려(내려보기 −0.06rad) 캐릭터 뒷모습과 콘텐츠를 함께 잡는다. 어깨 너머 고정 구도는 휴대폰에서 캐릭터가 화면 밖으로 나가서 쓰지 않았다.
- 다른 세계면: 위 구도 수치는 1.6×1.2m 작품 기준이다. 작은 화면(예: 0.55×0.41m)은 최소 거리 1.4m와 3.3m 뒤 카메라에 걸려 화면 세로의 약 8%로 작게 보이므로 다시 정한다. 의자처럼 「가서 앉는」 자리는 앉는 자세와 자리 겹침을 새로 정한다. 영상은 창 영상 하나만 써 봤다. 여러 영상을 동시에 틀면 동시 재생 수와 휴대폰 자동 재생 조건(muted·playsinline)을 따로 정한다.
- 확인: 누른 뒤 데스크톱과 세로 휴대폰에서 캐릭터 뒷모습과 콘텐츠 전체가 한 화면에 들어온다. 1인칭으로 만든다면 1600×900 화면에서 콘텐츠 가운데가 화면 가운데(800, 450)에 와야 한다.

7. 내 캐릭터와 3인칭
- 캐릭터 시안 2~3개를 Blender 백그라운드로 만들어 앞·옆·뒤로 렌더한 뒤 고른다. 웹용은 부위 6개(부위마다 관절 위치에 원점), 꼭짓점 색, 3,812 삼각형, 약 91KB GLB다. 뼈대 없이 코드로 팔다리 흔들기·통통 튀기·숨쉬기를 하고, 걸음 주기는 이동 속도(기준 2.6m/s)에 맞춘다.
- 공간은 구운 빛이라 실시간 조명이 없다. 캐릭터 재질은 자체 음영과 테두리 빛(미술관은 민트색)으로 어둠 속에서도 보이게 한다.
- 이동: 걷기 2.6m/s, 달리기 5.2m/s, 몸 반지름 0.32m로 wall_·col_ 상자와 충돌한다. 조작은 드래그로 둘러보기, 휠·두 손가락으로 거리, 바닥 누르기로 걸어가기, WASD·방향키(카메라 기준)다. 7px 넘게 움직이면 클릭이 아니라 드래그로 본다.
- 카메라: 캐릭터 머리 위 1.0m를 보며 뒤 3m(1.6~5m)에서 따라간다. 기본 내려보기 −0.24rad(−0.95~0.2). 반지름 0.18m의 카메라 구가 벽 상자에 막히면 그만큼 당기고, 너무 가까우면 머리 위로 올라가 내려다본다. 최저 높이는 0.4m다.

8. 다른 방문자(실시간 접속)
- 서버는 /api/presence WebSocket만 방 Durable Object(SQLite 저장, Hibernation API, ping 자동 응답)로 넘긴다. 방은 10개, 정원은 30명이고, 꽉 차면 다음 방으로 간다(모두 차면 혼자 본다). 방은 자동 배정이라 친구끼리 같은 방을 고르는 기능은 없다.
- 메시지: 서버 → 방문자 welcome(나, 이미 있는 사람들), join, move(id, x, z, 바라보는 방향, 걷는 중 여부), leave, wave(id, 이름), full. 방문자 → 서버 move, wave.
- 접속하면 자동 이름(형용사+세계의 낱말. 미술관은 미술 낱말, 예: 수줍은 물감)과 옷 색 8가지 중 하나를 받는다. 위치는 저장하지 않고 같은 방에만 중계한다. 다른 방문자는 같은 캐릭터 GLB를 색만 바꿔 그리며(부위당 그리기 1번), 30m 안에 있는 사람만 그린다.
- 인사: 👋 단추를 누르면 캐릭터가 1.6초 손을 흔들고, 10m 안에 있는 사람에게 이름과 함께 알림이 뜬다. 소켓당 2초에 1번이다.
- 다른 세계면: move에는 위치·방향·걷는 중 여부만 있다. 앉기처럼 남에게도 보여야 하는 상태와 자리 차지(두 사람이 같은 자리를 누를 때)는 메시지와 방 쪽 판정에 새로 더한다. 그대로 두면 각자 자기 화면에서만 앉은 것으로 보인다.
- 요청 아끼기: 움직일 때만 초당 4번 이하로 보낸다. 2초에 24개 넘게 보내는 소켓은 서버가 끊는다. 화면을 1분 넘게 떠나면 연결을 닫고, 서 있는 동안은 30초마다 ping을 보낸다(자동 응답이라 방을 깨우지 않는다). 끊기면 2·4·8·16초 뒤 네 번 다시 잇고(첫 연결을 포함해 다섯 번), 그래도 안 되면 새로고침이나 화면 복귀 전까지 멈춘다.
- 확인: 서버를 끄고 다섯 번 시도한 뒤 다시 잇기가 멈추는지 본다.

9. 소리
- 배경 음악: 생성한 연주곡을 MP3로 바꾸고 앞 3초·뒤 5초 페이드, −20 LUFS로 맞춘다. 첫 클릭·키 입력 때 재생하고, 끄는 단추를 둔다.
- 효과음은 소리 파일 없이 Web Audio로 합성한다: 걸음 주기가 0을 지날 때마다 발소리, 바닥 누르기 「뽁」, 콘텐츠 「띠링」, 패널 「뿅」, 단추 「톡」, 순간 이동 「반짝」. AudioContext는 첫 터치 때 깨운다. 끄기 설정은 기기에 기억한다(localStorage). 모닥불·풀벌레처럼 세계의 소리는 같은 합성 방식으로 더한다(다른 세계면).

10. 입구·화면·공개
- 로딩 화면 「빛의 문」은 정적 HTML에 넣어 JS보다 먼저 보이게 한다. 아치형 문이 엔진 진행 비율만큼(0.04→0.92) 열리고, 첫 프레임 뒤 빛 속으로 들어가 장면으로 넘어간다. 실패하면 문이 닫히고 안내가 나온다. 움직임 줄이기 설정이면 사라지기만 한다. 브라우저 상단 색은 밤 색(#0a0916)이다. 다른 세계면 문 모양과 색만 세계에 맞춘다.
- 3D 위의 UI 패널(메뉴·콘텐츠 정보 창)에는 흐림(backdrop-filter)을 쓰지 않는다. 휴대폰 GPU 부담과 배경에 따른 글자 대비 흔들림을 피해, 거의 불투명한 유리판(rgb(30 25 58 / .88), 패널 .96)을 쓴다.
- 공개: 첫 화면과 3D 자산은 정적 파일로 낸다(미술관: 공간 GLB 4.5MB, 라이트맵 1.7MB×2, 창 영상 2.5MB, 음악 3.8MB, 캐릭터 91KB). 서버(Worker)는 실시간 접속 같은 꼭 필요한 요청만 받는다. 개발 표시를 숨길지(운영 화면인지)도 서버가 아니라 브라우저 주소로 판단해 요청마다 서버 CPU를 쓰지 않는다. 미술관은 Next.js 16을 OpenNext로 Cloudflare Workers에 올렸다(무료 요금제: 요청당 CPU 10ms, 계정 하루 10만 요청).
- IP당 요청 제한 규칙을 둔다면 정적 자산 경로를 빼야 한다. 첫 화면 한 번에 정적 18개·Worker 4개 요청이 나서 "10초에 15회" 규칙에 막혀 429가 났다.
- 확인: 데스크톱과 세로 휴대폰(390×844)에서 로딩→입구→걷기→(3)의 행동(미술관은 콘텐츠 보기)→바로가기를 걸어 본다.

## Limits

- 미술관 말고 다른 세계로는 아직 만들어 보지 않았다. 레시피만 준 독립 에이전트로 계획까지 점검했다: 레트로 오락실·밤 숲속 캠핑장 모두 걷기·3인칭·소리·공개는 그대로 옮겨졌고, 공간·빛·효과·콘텐츠 자리는 요구사항에 맞춰 새로 정해야 했다. 이 판을 캠핑장으로 다시 점검했을 때 막힌 단계는 없었고, 남에게 보여야 하는 상태(앉기), 야외 하늘, 불꽃은 새로 정해야 했다.
- 불꽃·연기처럼 모양이 움직이는 효과는 없다. 미술관의 효과는 빛의 배율과 떠다니는 별가루뿐이다.
- 미술관의 밤 효과(오로라·별가루·하늘·물빛·안개)는 WebGPU에서만 켜진다. WebGL2 브라우저에서는 효과 없이 구운 낮의 공간이 보인다.
- 빛을 구워 둔 공간이라 모양이나 문·창 위치를 바꾸면 다시 구워야 한다. 물빛·안개는 미술관 창 위치에 맞춘 효과다.
- 실시간 접속은 방 10개·정원 30명으로 설계했다.
- 방문자가 콘텐츠를 올리는 기능, 로그인, 결제, 광고, 약관처럼 운영 서비스에 필요한 부분은 이 레시피에 없다. 친구끼리 같은 방에 들어가기, 여러 영상 동시 재생도 해 보지 않았다.
